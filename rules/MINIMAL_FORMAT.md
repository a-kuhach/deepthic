# Minimal format rules (CRITICAL)

Отправляется при каждом открытии окна агента (executor или reviewer).
Без этих правил фреймворк не сможет распарсить ответ.

## Разметка ответа

- Первая строка ответа: [ROLE].
- Со второй строки — ровно один fenced-блок PowerShell. Ничего до блока и после.
- Первая строка внутри блока: Write-Output "ROLE: <ТЕГ>".
- Не используй USER_CHAT.

## Маркеры внутри PS-скрипта (CRITICAL)

Точные строки через Write-Output, без украшений:

- Write-Output "USER_MSG: <текст>" — сообщение пользователю, выполнение продолжается.
- Write-Output "AGENT_PAUSE: <причина>" — пауза до ответа пользователя.
- Write-Output "AGENT_STOP: <причина>" — остановка пайплайна.
- Write-Output "AGENT_DONE: <итог>" — завершение задачи (только ANALYST при передаче PLANNER).

## Блокирующий вопрос (CRITICAL)

Ровно пара строк в одном PS-скрипте:

Write-Output "USER_MSG: <текст вопроса>"
Write-Output "AGENT_PAUSE: <короткая причина>"

Простой текст без маркеров (например Write-Output "1) ... ?") в Chat пользователя
не попадает — он виден только в PS Console.


## Исполнение PS-скриптов

PS-скрипт — твои глаза и руки. Через них ты читаешь файловую структуру проекта, видишь наполнение файлов, выполняешь команды доступных инструментов в консоли, получая вывод в ответном сообщении.

Убедись, что генерируемый тобой скрипт будет выполняться не более 15 минут. Для запуска более долгого скрипта необходимо обязательное разрешение пользователя, а сам скрипт должен будет породить запуск отдельного окна консоли (так как оригинальный скрипт будет убит принудительно при достижении критического таймаута в 30 минут). После одобрения пользователем, отправка такого скрипта (длительность > 15 минут) должна сопровождаться вызовом паузы (AGENT_PAUSE).
