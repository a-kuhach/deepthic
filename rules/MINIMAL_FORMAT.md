
# Minimal format rules (CRITICAL)

Отправляется при каждом открытии окна агента (executor или reviewer).
Без этих правил фреймворк не сможет распарсить ответ.

## Разметка ответа

- Первая строка ответа: [ROLE].
- Со второй строки — ровно один fenced-блок PowerShell. Ничего до блока и после.
- Первая строка внутри блока: Write-Output "ROLE: <ТЕГ>".
- Не используй USER_CHAT.

## Маркеры внутри PS-скрипта (CRITICAL)

Точные строки через Write-Output, без украшений:

- Write-Output "USER_MSG: <текст>" — сообщение пользователю, выполнение продолжается.
- Write-Output "AGENT_PAUSE: <причина>" — ТОЛЬКО для общения с ПОЛЬЗОВАТЕЛЕМ, пауза до ответа пользователя.

## ОБЯЗАТЕЛЬНЫЙ USER_MSG В КАЖДОЙ ИТЕРАЦИИ (CRITICAL)

Каждый PS-скрипт ДОЛЖЕН содержать хотя бы одну строку:
  Write-Output "USER_MSG: <краткий статус>"

Примеры допустимых статусов:
  Write-Output "USER_MSG: диагностика лога: 3 дефекта, читаю X.Y.Z"
  Write-Output "USER_MSG: правки применены, сборка pass"
  Write-Output "USER_MSG: готово к ревью"

Зачем: framework показывает в Chat только USER_MSG-строки. Диагностика (Write-Output без префикса) идёт в PS Console и в чате не появляется. Если в скрипте нет ни одного USER_MSG, пользователь видит "тишину" в чате — и не понимает, что итерация была.

Блокирующий вопрос (пара USER_MSG: + AGENT_PAUSE:) удовлетворяет этому требованию — отдельного USER_MSG не требуется.

Если итерация чисто техническая (только диагностика) — всё равно дай короткий USER_MSG-статус: Write-Output "USER_MSG: диагностика — <1-2 слова о результате>".

## ОДНОСТРОЧНЫЙ USER_MSG (CRITICAL)

USER_MSG должен быть ОДНОСТРОЧНЫМ. Никаких встроенных переносов строк внутри текста.

Запрещено: Write-Output ("USER_MSG: " + $multiLineString), где $multiLineString содержит `n.
Запрещено: Write-Output "USER_MSG: строка1`nстрока2" (PS backtick-n внутри кавычек).

Разрешено для нескольких пунктов:
  Write-Output "USER_MSG: 1) первый"
  Write-Output "USER_MSG: 2) второй"
  Write-Output "USER_MSG: 3) третий"
Каждый пункт — отдельный Write-Output "USER_MSG: ...".

Или через разделитель в одну строку:
  Write-Output "USER_MSG: 1) первый; 2) второй; 3) третий"

Причина: framework парсит stdout построчно; embedded `n внутри одной Write-Output-строки
приводит к тому, что весь блок (включая диагностику) склеивается в один Agent-чат-месседж.

Диагностика в PS-Console: любые Write-Output БЕЗ префикса USER_MSG (голый текст,
дампы строк, grep-результаты) идут в PS-Console и НЕ попадают в чат. Это правильно —
чат только для сообщений пользователю, консоль для технического вывода.

## Блокирующий вопрос (CRITICAL)

Ровно пара строк в одном PS-скрипте:

Write-Output "USER_MSG: <текст вопроса>"
Write-Output "AGENT_PAUSE: <короткая причина>"

Простой текст без маркеров (например Write-Output "1) ... ?") в Chat пользователя
не попадает — он виден только в PS Console.

## Исполнение PS-скриптов

PS-скрипт — твои глаза и руки. Через них ты читаешь файловую структуру проекта, видишь наполнение файлов, выполняешь команды доступных инструментов в консоли, получая вывод в ответном сообщении.

Убедись, что генерируемый тобой скрипт будет выполняться не более 15 минут. Для запуска более долгого скрипта необходимо обязательное разрешение пользователя, а сам скрипт должен будет породить запуск отдельного окна консоли (так как оригинальный скрипт будет убит принудительно при достижении критического таймаута в 30 минут). После одобрения пользователем, отправка такого скрипта (длительность > 15 минут) должна сопровождаться вызовом паузы (AGENT_PAUSE).

## FORBIDDEN: MULTIPLE FENCED CODE BLOCKS

Your response MUST contain exactly ONE opening ``` and exactly ONE closing ```.
DO NOT output multiple fenced blocks in a single response.
DO NOT nest fenced code blocks inside one another.

Any response containing more than two ``` lines is INVALID and will be rejected, triggering a mandatory regeneration.
